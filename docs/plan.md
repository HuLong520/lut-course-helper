# LUTHelper 重构实施计划

## 1. 目标

在 `LUTHelper/` 中建立独立项目，以 `UItest/UI_Plus.py` 作为功能基线，重构为分层 Python 桌面应用，最终交付两个 Windows x64 单文件绿色版：

- 正式版 `抢课助手.exe`：不包含 OCR。
- 开发版 `LUTHelper-dev.exe`：包含 ddddocr。

正式版和开发版均使用 PySide6 + PySide6-Fluent-Widgets[full]，以 GPLv3 开源。项目从第一天使用独立 Git 仓库，旧目录只读保留，全部验收后才归档旧 UI。

## 2. 已确认的产品决策

- 界面方向：Fluent 桌面风，暖白背景、深墨文字、青绿色强调色。
- 登录方式：启动即弹出不可绕过的登录对话框。
- 主导航：课程、全校课程、已选课程，共三页。
- 课程页：左侧课程检索、右侧抢课课程组，日志为底部覆盖式抽屉。
- 课程行内使用圆形“加号/对勾”按钮，点击加入、再次点击取消，不设底部批量加入栏。
- 单教学班课程在右侧直接显示为紧凑卡片，多教学班才使用可折叠课程组。
- 已选课程与课表合并为同一页，左右并排；退课记录折叠展示，首版不实现退课操作。
- 抢课任务按 KCH 课程代码分组：首个教学班为首选，其余按加入顺序为备选。
- 同一课程组同一时刻只运行一个教学班；首选不可选时切换到下一个备选。
- 首选恢复余量时，暂停当前备选并切回首选。
- 组内任一教学班成功，停止本组其余任务。
- 组内顺序只能在整组未开始时拖拽调整。
- 课程组左侧箭头专门控制首选/备选的展开收起，右侧“…”负责课程组菜单。
- 课程组菜单提供查看详情、重置和删除整组操作。
- 抢课队列顶部使用单个“开始全部 / 全部停止”状态按钮，点击后切换文案、图标和红色停止态。
- 全局参数：请求间隔 50–10000ms，每课线程使用 1–20 的可输入数字框，抢到即停默认开启。
- 固定请求间隔，不实现指数退避。
- 全局定时精确到秒，仅在前台进程运行；到点强制启动所有非成功课程组，从首选重新开始；错过时恢复后立即启动。
- 失败只写日志和更新状态，不弹窗；成功和定时触发显示 5 秒 InfoBar 并播放系统提示音。
- 全校课程进入页面自动加载，顶部可手动刷新；首次 pageSize=500，返回空时自动减半重试；关键词和校区只在本地筛选。
- 已选课程保留原始接口行和解析时段；课表优先使用 `SKZC/SKXQ/KSJC/JSJC`，回退到 `teachingPlace` 文本解析。
- 已选课程详情只读，不显示“加入抢课队列”；详情遮罩保持轻量，不能过度影响查看其余课程。
- 账号密码明文保存在 exe/项目根目录的 `accounts.json`；任务、日志、筛选、token 全部只在内存中。
- 不迁移旧 `config.json` 或 QSettings；首次登录成功后才创建 `accounts.json`。
- 正式版隐藏 OCR 入口并排除 OCR 依赖；开发版可自动识别验证码，失败最多刷新重试 3 次后回退手输。
- 不使用托盘常驻、自动更新、系统计划任务或自动退课。
- 首版成功判定沿用旧版 `code=200` / 关键词逻辑，WebSocket 和已选课程二次核验只预留接口。

## 3. 分阶段实施

### 阶段一：HTML 视觉原型

产出：

- `prototype/login.html`
- `prototype/index.html`
- `prototype/assets/styles.css`
- `prototype/assets/app.js`
- `prototype/assets/mock-data.js`
- `docs/ui-spec.md`

原型使用原生 HTML/CSS/JavaScript，无构建步骤。字体允许 CDN，图标使用内联 SVG。页面必须能通过任意静态服务器打开，Edge 最新版为验收基准。

本阶段只验证视觉和信息架构，不连接真实接口。确认后再进入 Qt 实现。

验收：

- 登录页和三个主页面可点击切换。
- 课程筛选、列菜单、批量加入、重复教学班弹窗、组内拖拽、全局定时、日志抽屉、课表周次切换可操作。
- 1440×900、1280×720、1024×700 三档布局可用。
- 无 JS 语法错误，关键页面无空引用。

### 阶段二：Fluent Qt 主壳与静态页面

- 在 `LUTHelper/` 内创建独立 `.venv`，锁 Python 3.12。
- 安装 PySide6、PySide6-Fluent-Widgets[full]、pytest、pytest-qt。
- 创建 `src/luthelper/` 包和 `python -m luthelper` 入口。
- 实现 Fluent 自定义标题栏、登录弹窗和三页主壳。
- 先接模拟数据，完成视觉验收后再接真实服务。
- 默认窗口 `1440×900`，最小 `1080×680`，首次居中。
- 窗口宽度低于 1280px 时，课程详情改为抽屉。
- 日志抽屉覆盖展开，不压缩主内容。
- 不使用底部状态栏。

验收：

- 三页导航与登录弹窗正常。
- 100%、125%、150% 高 DPI 下布局可用。
- Qt 截图与 HTML 原型同尺寸人工对照。

### 阶段三：业务、登录、查课与抢课

实现分层：

```text
domain/           数据模型、错误、协议、时钟
application/      认证、课程、抢课协调、定时器、日志
infrastructure/   LutClient、账号文件、OCR、单实例、系统提示音
presentation/     壳、页面、ViewModel、控件、主题
```

关键接口：

- `LutClientProtocol`：登录配置、验证码、登录、学生、批次、确认、课程列表、已选课程、加入课程、关闭。
- `CredentialStore`：加载、upsert、删除、记录登录时间。
- `RobCoordinator`：添加课程、组内排序、开始/暂停/停止组、全局定时启动、清空任务。
- `Scheduler`：QTimer 每秒检查，支持设置、取消、到点触发、错过立即触发。
- `Clock`：`now()` 和 `monotonic()`，测试注入 FakeClock。
- `TaskRunner`：生产环境 QThread，测试环境同步 FakeRunner。

UI 不直接创建网络线程、不直接持有请求库，也不直接修改业务对象。页面 ViewModel 负责把 AppState 投影为显示字段和命令。

## 4. 业务规则

### 4.1 课程组与首选/备选

- 按课程代码 `KCH` 分组。
- 同一课程组内禁止重复 `JXBID`；重复时弹窗“忽略 / 移动已有实例到末尾 / 取消”，默认忽略。
- 启动组时只启动首选。
- 首选收到明确“已满 / 人数已满 / 容量已满 / 不可选”时，停止首选线程并启动下一个备选。
- 无法识别不可选原因时继续按原间隔重试。
- 备选运行期间每 5 秒刷新课程列表，首选仍满足 `numberOfSelected < classCapacity` 且 `SFCT != 1` 时切回首选。
- 刷新连续失败 3 次后暂停自动恢复，等待用户处理。
- 切换到备选前刷新该班次 `secretVal`。
- 同一课程组任一任务成功，停止本组全部线程；其他课程组不受影响。
- 组内顺序只在整组未开始时允许拖拽。
- 预计线程数 = 活跃教学班 × 每课线程；超过 20 琥珀色警告，超过 50 红色警告，但都不阻止。

### 4.2 全局定时

- 任务区顶部提供全局定时开关、时间选择器、倒计时。
- 精确到秒；QTimer 在主线程每秒检查。
- 到点时停止当前运行任务，跳过已成功组，其余组全部从首选重新开始。
- 系统恢复或卡顿导致错过时立即启动，并记录实际启动时间。
- 定时触发后播放系统提示音并显示 InfoBar。

### 4.3 自动查课

- 登录成功后读取 `/elective/user` 的 `electiveBatchList`。
- 默认选第一个可用批次；需要确认时自动调用 `/elective/batch/confirm`。
- 按 `TJKC → FANKC → TYKC → XGKC` 顺序查询，展示第一个非空类型。
- 某类型请求失败立即停止探测，显示 InfoBar，不继续请求。
- 登录成功后异步查课，显示加载骨架，不阻塞主界面出现。
- 课程类型切换保留任务队列；类型结果在会话内缓存，手动查询强制刷新。
- 校区切换立即重新查询，任务队列保留。

### 4.4 全校课程

- 只查询 `ALLKC`，请求不带 campus。
- 首次 pageSize=500，服务器返回空则自动减半重试。
- 加载可取消；取消后保留已加载数据。
- 加载完成后只在本地做关键词、校区、余量和冲突筛选。

### 4.5 已选课程与课表

- 进入页面刷新，另提供手动刷新，不后台轮询。
- 保留原始接口行和解析时段双份数据。
- 课表优先使用结构化 `SKSJ` 字段。
- 动态节次最少 1–10 节，有更晚课程扩展到 12 节。
- 周次选择“全部周次”和 1–20 周。
- 冲突课程全部加红色左边框和图标，详情列出冲突对象。
- 未解析进网格的课程显示在“未排入网格”列表。
- 课程块按课程名稳定哈希取 6 个低饱和颜色。

### 4.6 登录、账号与退出

- `accounts.json` 路径：源码运行在项目根，打包后在 exe 同级。
- 格式：

```json
{
  "version": 1,
  "accounts": [
    {
      "username": "学号",
      "password": "明文密码",
      "last_used_at": "ISO-8601 时间"
    }
  ]
}
```

- UTF-8、缩进 2、`ensure_ascii=False`，直接覆盖写入。
- 不预置文件；登录成功后创建。
- 账号按最近使用排序。
- 取消记住密码并成功登录后删除该账号记录。
- 支持删除账号，删除前确认。
- 写入失败只警告，不阻止登录和当前会话使用。
- token 只存在进程内，不跨重启保存。
- 退出登录时先确认停止运行中任务，再清空全部内存状态并重新显示登录弹窗。
- 关闭窗口时若有运行中或定时任务，先确认停止，再退出。

## 5. 打包与交付

- 构建输出到 `release/`：
  - `release/抢课助手.exe`
  - `release/LUTHelper-dev.exe`
- 两个产物均为 onefile、Windows x64、无控制台。
- 正式构建注入 `LUTHELPER_BUILD=release`，排除 ddddocr、onnxruntime 等 OCR 依赖，并隐藏 OCR 入口。
- 开发构建安装 `requirements-ocr.txt`，显示自动识别入口。
- 不使用 UPX。
- 只排除明确不用的 Qt 模块和插件，先保证稳定性。
- 打包版显示轻量 Splash；源码运行不显示。
- 使用 Windows 命名互斥量限制单实例；重复启动提示“程序已运行”后退出。
- 未捕获异常尽量继续运行，写入内存日志并显示 InfoBar。
- 构建完成后记录正式版和开发版实际体积，与旧版 34.92 MB 对比。

## 6. 测试计划

### 6.1 单元测试

- 星期、节次、周次解析；结构化课表字段与文本回退。
- AES-ECB 加密、验证码、批次、登录错误分类。
- 课程模型、课程组和任务状态汇总。
- 首选/备选切换、首选恢复、组成功停止、组内排序。
- 全局定时、错过时间立即启动、暂停组强制重启。
- 账号 JSON 创建、更新、删除、最近使用排序、写入失败。
- 日志环形容量、筛选和导出。

### 6.2 Qt 无头测试

- `python -m luthelper` 启动。
- 登录弹窗不可绕过。
- 登录失败 InfoBar、验证码错误自动刷新。
- 三页导航、筛选、列菜单、批量加入。
- 重复课程对话框、任务组展开、日志抽屉。
- 课表周次切换、冲突标记、未排入列表。

### 6.3 视觉验收

- HTML 原型在 Edge 最新版逐页打开。
- 保存登录页、课程页、全校课程页、已选课程页在 1440×900、1280×720、1024×700 下的截图。
- Qt 首版同尺寸截图后人工对照，允许字体和控件差异导致的轻微布局修正。

### 6.4 手工业务验收

真实登录、查课和抢课不在自动化测试中触发，避免真实写操作和限流。需要你明确授权后手工执行：

- 验证码登录。
- 学生信息和批次加载。
- 自动查课。
- 已选课程加载和课表解析。
- 加入抢课队列。
- 首选/备选切换。
- 停止和退出清理。

## 7. GPL 合规

- 项目根包含 GPLv3 `LICENSE`。
- `README.md` 说明第三方组件、GPLv3 义务、源码获取方式和构建步骤。
- 正式发布 exe 时同时提供对应源码。
- 发布前补充实际源码仓库 URL。
- 其他依赖优先使用 MIT、BSD、Apache、PSF 等宽松许可。
- 未来如果闭源商业分发，需要替换 Fluent 组件适配层或取得相应商业授权。

- 把 `UItest/`、根目录旧 UI 文件、旧 spec 和旧 exe 移到 `archive/legacy-ui/`。
